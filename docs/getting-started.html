Getting Started on Windows, macOS and Linux

Four one-time setup steps, then save a Markdown file to build it.

  1. Install Pandoc and a LaTeX distribution

    Pandoc does the document conversion; a LaTeX distribution (providing xelatex) is only needed for PDF and Beamer output.

    Windows 
    winget install --id JohnMacFarlane.Pandoc

    Then install MiKTeX for xelatex.

    Linux 
    sudo apt install pandoc texlive-xetex texlive-latex-extra texlive-fonts-extra
    macOS 
    brew install pandoc

    Then install MacTeX for xelatex.

    Verify both are on PATH:

    pandoc --version
xelatex --version

  2. Check that Python is installed

    Windows 
    python --version
    Linux / macOS 
    python3 --version

    Common issue: Python may be aliased differently on your system. If python/python3 isn't found, try py, py3, or a version-specific name like python3.13.

    If none of those print a Python 3 version, install it from python.org first.

  3. Create the virtual environment

    The workspace expects a .venv folder at the root of the repo.

    Windows (PowerShell) 
    py -3.13 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r _core/scripts/requirements.txt
    Linux / macOS 
    python3.13 -m venv .venv
./.venv/bin/python -m pip install -r _core/scripts/requirements.txt

  4. Configure VS Code settings

    _core/vscode-settings-templates/ has ready-to-paste templates. Copy the one matching your OS into a new .vscode/settings.json:

    Windows (PowerShell) 
    copy _core\vscode-settings-templates\settings.windows.json .vscode\settings.json
    Linux / macOS 
    cp _core/vscode-settings-templates/settings.linux.json .vscode/settings.json

    Then install the recommended extensions: Run on Save (required for the build-on-save workflow) and Highlight (optional syntax highlighting for math and solution blocks).

  5. Save a Markdown file and watch it build

    Open one of the ready-to-use files in _core/examples/, or start your own with mdoffice.make-pdf: true in the frontmatter. Saving the file runs the build automatically and drops the output next to it.

Full reference: the README covers every frontmatter key, custom LaTeX themes, and troubleshooting for each step above.
